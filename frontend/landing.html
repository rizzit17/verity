Physical Page Provenance

Deterministic PDF Coordinate Grounding Architecture

Why Standard RAG Fails Financial Filings

Standard Retrieval-Augmented Generation (RAG) splits text into arbitrary token lengths, stripping out table row associations and physical page metadata. When an LLM asserts a revenue figure, human auditors cannot trace the quote back to the statutory page without manual document searching.

VERITY GROUNDING STANDARD ZERO HALLUCINATION PROTOCOL
  • ▸ PyMuPDF Engine: Ingests native text blocks with exact page number indices and line-coordinate bounding boxes.
  • ▸ Verbatim Anchoring: Facts must contain exact verbatim string quotes from the source text chunk. Any synthetic metric without an anchor is rejected.
  • ▸ Auditable Export: Every claim in the knowledge graph includes immutable attributes: source_file, page_num, and verbatim_quote.

Scale & Currency Harmonization

Corporate filings frequently mix disparate financial notations - such as Lakhs, Crores, Millions, and Billions - often within the same company's prospectus versus its statutory audited report. Verity automatically normalizes numbers to standard base units before running reconciliation algorithms.

INDIAN NOTATION MAPPING
1 Lakh = 100,000 (10⁵)
1 Crore = 10,000,000 (10⁷)
100 Crores = 1 Billion (10⁹)

System Architecture & Technology Stack

End-to-End Pipeline Infrastructure

Architecture Overview

Verity is constructed as a high-integrity, modular backend service with a modern responsive frontend. The architecture is decoupled into Ingestion, Extraction, Vector Indexing, Reasoning, and Storage layers.

CORE TECHNOLOGY STACK
▸ FastAPI v0.115: High-performance async ASGI REST API
▸ PyMuPDF (fitz): High-precision PDF parser with page spans
▸ Sentence Transformers: all-MiniLM-L6-v2 vector embeddings
▸ Google Gemini: Multi-step deterministic reasoning engine
▸ Numpy Cosine Index: Sub-millisecond candidate pair search
▸ Vanilla WebGL / OGL: Hardware-accelerated dynamic UI
PIPELINE DATAFLOW
  1. PDF Ingestion: Multi-page documents parsed into page-indexed text blocks.
  2. Fact Extraction: Claims mined with metric, entity, date, value, and verbatim quote.
  3. Candidate Matching: Metric & subject strings vectorized and paired via cosine clustering.
  4. LLM Reconciliation: Dual claims evaluated for Corroboration, Contradiction, or Nuance.
  5. Audited Knowledge Layer: Results published to UI and persistent JSON/SQLite store.
